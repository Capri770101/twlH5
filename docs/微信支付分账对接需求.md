# 跳舞兰 H5 官网 · 微信支付分账体系对接需求说明

> 用途：H5 官网要复用「跳舞兰微信支付服务商 + 各合作花店子商户 + 自动分账」这套已经在小程序跑通的体系。本文档交给负责小程序支付的同事，确认要提供/对齐的物料与对接点。

---

## 一、背景与目标

- 跳舞兰已开通微信支付**服务商**（sp_mchid），并为 10+ 合作花店配置了**子商户（sub_mchid）**，绑定了**自动分账**规则；小程序平台已跑通「下单 → 支付 → 自动分账给花店」。
- 现要上线 **H5 官网**（独立网页，暂时部署在 `http://8.138.248.173:8088/`，后续配域名 + HTTPS），希望**直接复用同一套服务商 + 分账体系**，不再单独申请或重新配置分账关系。
- 目标：H5 官网用户下单 → 按「归属店铺」携带该花店的 `sub_mchid` → 调起微信支付 → 支付成功后沿用服务商后台已配置的**自动分账**，把款项分给对应花店。

---

## 二、对接模式（与小程序一致）

采用微信支付 **服务商模式（partner）**，复用小程序同一套配置：

1. 复用同一个服务商商户号 `sp_mchid`（跳舞兰主体）。
2. 每笔订单根据「归属店铺」携带该店的 `sub_mchid`，走 `/v3/pay/partner/transactions/*` 接口。
3. 下单请求带 `settle_info.profit_sharing = true` → 微信支付成功后**自动触发已配置的分账**，把资金分给花店子商户。H5 端不重复调分账接口。
4. H5 只是新增的「销售渠道」，只要能拿到正确的 sub_mchid 映射、且分账规则在服务商后台已配好，即可直接分账，无需重建分账关系。

### A. 服务商主体参数（跳舞兰，一套）

| 参数 | 说明 | 备注 |
|---|---|---|
| sp_mchid | 服务商商户号 | 跳舞兰主体 |
| sp_appid | 服务商 AppID | 公众号 / 小程序 AppID（JSAPI 微信内支付需要） |
| APIv3 密钥 | APIv3 Key | 商户平台 → 账户中心 → APIv3 密钥 |
| 商户证书序列号 | apiclient_cert 的 serial | |
| 商户私钥 | apiclient_key.pem | 仅后端使用，不进仓库 |
| 平台证书 | 微信支付平台证书 | H5 后端可运行时自动下载，但需服务器能访问微信接口 |

### B. 子商户映射（每个花店一条）

- 给我一份完整的 **店铺 → sub_mchid** 映射（这 10 几家花店的 shopId 与对应 sub_mchid）。
- 确认每个子商户是否需要 `sub_appid`（H5 场景多数复用服务商 sp_appid，留空即可；如子商户有独立 AppID 请一并给）。
- 我们系统的 `shops` 表已预留 `sub_mchid / sub_appid / settle_ratio` 字段，可落库；也支持先放一个 `submch.json` 配置文件（样例见第四节）。

### C. 分账规则确认（最重要）

1. 分账是在**服务商后台已预置**（支付成功自动分账），还是需要**接口主动传分账比例 / 接收方**？
2. 如果是后台预置：H5 只需 `profit_sharing = true` 即可触发，和现有小程序逻辑一致。
3. 如果是接口传：请给我分账接收方配置（各店分账比例 / 固定金额 / 接收方账号），我们再对接分账接口。

### D. 支付场景确认

- H5 官网主要在**微信内**打开（→ 走 JSAPI，需用户 openid），还是**微信外浏览器**（→ 走 H5 支付 / MWEB，返回 h5_url 跳转中间页），还是 **App 内**？
- 我们已同时实现 JSAPI 和 H5 两种，按 UA 自动切换；请确认主流量入口，便于联调与 openid 获取方案（微信内 JSAPI 需网页授权拿 openid，或复用小程序 unionid 体系）。

### E. 回调与域名

- 支付成功**回调地址**必须是公网 HTTPS。请确认 H5 官网上线域名（建议 `https://h5.tiaowulan.com` 之类），我们把 `WXPAY_NOTIFY_URL` 指过去，并把该域名加入服务商「支付回调配置」。
- H5 支付完成后返回页（redirect_url）域名也需与商户平台「H5 支付域名」一致。

## 四、H5 官网侧已落地的技术实现（供对齐 / 排查）

后端（Node，部署 `8.138.248.173:8088`，用户态运行，零依赖静态托管 + `/agent` 反代）：

- `server/src/wxpay.js`：微信支付 v3 客户端（RSA-SHA256 签名、回调验签、AES-256-GCM 回调解密、平台证书自动获取）。
- `server/src/pay.js`：支付路由
  - `POST /api/pay/order`：按 `tradeType` 选 JSAPI（`partner/transactions/jsapi`）或 H5（`partner/transactions/h5`），自动带 `sub_mchid` + `settle_info.profit_sharing = true`。
  - `GET /api/pay/query/:outTradeNo`、`POST /api/pay/close`、`POST /api/pay/refund`、`POST /api/pay/notify`（验签 + 解密 + 落单）。
- 配置：`server/config/submch.json`（shopId → subMchid 映射，样例 `submch.example.json`）；`server/.env`（WXPAY_* 变量，样例 `.env.example`）。
- 数据库：`shops` 表已加 `sub_mchid / sub_appid / settle_ratio` 三列（见 `server/sql/shops_submchid.sql`）。
- 前端：`Checkout.vue` 按 UA 自动选 JSAPI/H5；`src/utils/wxpay.js` 微信内调起支付。

> 当前状态：H5 后端尚未注入真实 `WXPAY_*` 值，支付走 mock；拿到第三节物料后即可切真实支付。
