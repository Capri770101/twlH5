> 检查日期：2026-09-15　|　方式：代码只读审查（4 条线并行）+ 关键项人工复核　|　范围：全站页面与业务流程

## 一、结论摘要

- **功能覆盖是完整的**：19 条路由覆盖浏览、下单、支付、订单、退款、评价、登录注册、地址、AI 顾问、收藏、优惠券，页面级体验在前一轮已优化过。
- **但交易链路存在多处高危缺陷**——支付回调进不来、下单可改价、支付金额可篡改、短信万能码在生产可用。这些不修，真实订单跑不通，且存在**资金损失风险**。
- 本轮已修复 **8 项**（含 4 项资损/安全级）；另有 **6 项 P1 + 6 项 P2** 需决策或后续处理，其中最关键的是「订单状态由谁推进」这一**产品级缺口**。

---

## 二、检查范围与方法

**覆盖流程**：商品浏览 → 分类/搜索 → 详情 → 加购 → 购物车 → 结算 → 下单 → 支付 → 订单列表/详情 → 取消/退款 → 评价；账号（注册/三种登录/登出）；地址管理；AI 顾问对话与卡片；收藏、优惠券、DIY 方案、分享。

**方法**：按「订单主流程 / 账号与地址 / 浏览与 AI 顾问 / 前后端接口契约」四条线并行只读审查，再对涉及金额与安全的关键结论逐条人工复核代码。

| 2 | 回调落库失败仍返回 200 成功 | **钱已收、订单仍待付款**（微信不重试） | 落库失败返回 5xx，让微信重试 | `server/src/pay.js` |
| 3 | 支付下单直接用前端传的金额，不校验订单 | **可篡改为 1 分钱支付** | 按数据库订单校验「存在 + 待支付 + 金额一致」，金额以库为准 | `server/src/pay.js` |
| 4 | 下单服务端仍信任前端传的商品单价 | **可传 0.01 元下单**（原先只防了总价） | 按商品库权威价格重算，取不到价即拒单 | `server/src/orders.js` |
| 5 | 商品映射丢掉店铺归属（数据源其实有） | 支付/退款**找不到子商户** → 静默失败 | 映射补出 `shopId / shopName / shopCity` | `server/src/mapping.js` |

| 8 | 地址省市区字段错位（产出 `province/city/district`，接口只读 `region`） | **订单地址不完整**，配送风险 | 补 `region` + 兼容兜底 + 结算页展示完整地址 | `AddressPicker.vue` `api.js` `Checkout.vue` |

## 四、待决策 / 待修

### P1（建议尽快处理）

| 问题 | 影响 | 建议 |
|------|------|------|
| **订单状态机后半段没有推进入口**（代码里只有「待支付→已支付」，没有 制作中/配送中/已完成 的写入） | 「制作中/配送中/已完成」三个 tab 恒为空；评价只对「已完成」开放 → **用户永远无法评价** | 需明确由谁推进（商家端 / 后台 / 定时任务）——**产品级缺口** |
| 多店购物车被合并成一单（`shopId` 只取第一家店） | 发货归属与**分账对象错误** | 按店铺拆单 |
| 优惠券未闭环（结算只做硬编码满减，从不读券；核销入口无调用） | 领券中心/我的优惠券是**死链路**，券永远用不掉 | 接入结算用券，或先下线券入口 |
| 微信内 `openid` 未取（订单页重付传空字符串） | 微信内重新支付必报错 | 从登录态取 `openid` |
| 登录态只判「有 token」不校验有效期；订单接口 401 会回退 mock | token 过期后仍显示"已登录"，**可能展示假订单** | 解析过期 / 401 即登出跳登录 |
| 取消订单不关闭微信预支付单 | 已取消的订单仍可能被付款成功 | 取消时同步关单 |

### P2（优化 / 后续）

- **图片资源**：mock 引用的 `/images/*.jpg` 大量 404、商品 `images` 字段恒为空 → 列表与详情大图**全部降级为 emoji**（代码里已改判 `image` 字段可缓解）。
- **仅本地存储**：收藏、地址、评价、DIY 方案都存 localStorage → 换设备即丢、与账号脱节。
- **mock 静默回退**：真实接口失败会自动回退假数据，用户可能把演示数据当真实（建议页面标注"演示数据"）。
- 搜索失败被吞成"没有找到"；防抖无请求序号（慢响应会覆盖新结果）。
- AI 流式解析只按 `\n\n` 切分，CRLF 或末段无空行时会丢事件。
- 分账：主动分账金额写死 0、从订单号解析店铺 id 必然失败（目前靠平台自动分账）。

## 六、建议的行动顺序

1. **短信资质到位后**，第一时间真机验证「注册 → 登录 → 下单」闭环（已修的部分需真环境回归）。
2. **明确订单状态由谁推进**（商家端/后台）——不解决，订单永远停在「待接单」，评价功能等于废掉。
3. **决定优惠券是否上线**：要么接入结算用券，要么暂时下线入口。
4. **多店拆单**：若业务上存在"一单跨多店"，必须拆；否则分账会对错对象。
5. **补图片资源**：体验层面最直观的短板。
