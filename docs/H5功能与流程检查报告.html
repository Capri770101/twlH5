一、检查范围与方法

覆盖流程：商品浏览 → 分类/搜索 → 详情 → 加购 → 购物车 → 结算 → 下单 → 支付 → 订单列表/详情 → 取消/退款 → 评价；账号（注册 / 三种登录 / 登出）；地址管理；AI 顾问对话与卡片；收藏、优惠券、DIY 方案、分享。

方法：按「订单主流程 / 账号与地址 / 浏览与 AI 顾问 / 前后端接口契约」四条线并行审查，再对涉及金额与安全的关键结论逐条人工复核代码。

二、已修复（8 项）

#问题影响修复
1支付回调拿不到原始 body（JSON 解析先消费了请求流）验签必失败 回调永远进不来 → 订单永不转「已支付」JSON 解析跳过 /api/pay/notify，交给 express.raw
2回调落库失败仍返回 200 成功钱已收、订单仍待付款（微信不重试）落库失败返回 5xx，触发微信重试
3支付下单直接用前端传的金额，不校验订单可篡改为 1 分钱支付按数据库校验「存在 + 待支付 + 金额一致」，金额以库为准
4下单服务端仍信任前端传的商品单价可传 0.01 元下单（原先只防了总价）按商品库权威价重算，取不到价即拒单
5商品映射丢掉店铺归属（数据源其实有）支付/退款找不到子商户 → 静默失败映射补出 shopId / shopName / shopCity
6短信 debug 万能码在生产环境可用任意手机号填 123456 即可登录生产默认禁用 debug（需显式开关才放行）
7登录/注册网络失败回退 mock 假成功提示"登录成功"但库里没账号一律抛错；并修正会导致 403 的 bindUserId 下发
8地址省市区字段错位（产出与读取字段名不一致）订单地址不完整，配送风险补 region + 兼容兜底 + 结算页展示完整地址

三、待决策 / 待修

P1 —— 建议尽快处理

问题影响建议
订单状态机后半段没有推进入口（只有「待支付→已支付」）制作中/配送中/已完成三个 tab 恒为空；评价只对「已完成」开放 → 用户永远无法评价明确由谁推进（商家端 / 后台 / 定时任务）——产品级缺口
多店购物车被合并成一单发货归属与分账对象错误按店铺拆单
优惠券未闭环（结算只做硬编码满减，从不读券）领券中心 / 我的优惠券是死链路接入结算用券，或先下线入口
微信内 openid 未取（订单页重付传空）微信内重新支付必报错从登录态取 openid
登录态不校验有效期；订单接口 401 会回退 mocktoken 过期仍显示"已登录"，可能展示假订单过期 / 401 即登出跳登录
取消订单不关闭微信预支付单已取消的订单仍可能被付款成功取消时同步关单

P2 —— 优化 / 后续

  • 图片资源：mock 引用的图片大量 404、商品 images 字段恒为空 → 列表与详情大图全部降级为 emoji。
  • 仅本地存储：收藏、地址、评价、DIY 方案都存 localStorage → 换设备即丢、与账号脱节。
  • mock 静默回退：真实接口失败会自动回退假数据，用户可能把演示数据当真实（建议标注"演示数据"）。
  • 搜索失败被吞成"没有找到"；防抖无请求序号（慢响应会覆盖新结果）。
  • AI 流式解析只按 \n\n 切分，CRLF 或末段无空行时会丢事件。
  • 分账：主动分账金额写死 0、从订单号解析店铺 id 必然失败（目前靠平台自动分账）。

五、建议的行动顺序

1. 短信资质到位后，第一时间真机验证「注册 → 登录 → 下单」闭环（已修部分需真环境回归）。
2. 明确订单状态由谁推进（商家端 / 后台）——不解决，订单永远停在「待接单」，评价功能等于废掉。
3. 决定优惠券是否上线：要么接入结算用券，要么暂时下线入口。
4. 多店拆单：若业务存在"一单跨多店"，必须拆；否则分账会对错对象。
5. 补图片资源：体验层面最直观的短板。
