二、六项问题逐条说明

1. 服务器（旧机已弃置，等待新服务器）

现状
三段式架构：① 静态站点 + 智能体反代（Node，:8088）→ ② Nginx（:443，/→8088、/api/→4000）→ ③ 业务后端（Express，:4000）。当前部署强绑定旧服务器固定 IP，仓库内尚无 systemd / 部署脚本，静态服务靠人工后台常驻。
待办
开发侧：硬编码 IP / 域名 / 端口全部外置为环境变量；补齐 Nginx 配置、进程守护（systemd）、一键部署脚本。交付侧：新服务器开通 → 装环境（Node + Nginx + MySQL）→ 部署迁移 → 证书迁移 → 域名切换。
依赖
新服务器（IP、登录方式、规格）
预估
服务器到位后 1~2 天

2. 数据库接入（连接小程序数据库）

现状
现有两套库：业务库 h5_shop（本机 MySQL，承载用户 / 地址 / 订单 / 支付 / 短信表，建表脚本已入库）；历史只读库已弃用于读路径。代码库中目前没有任何「小程序数据库」连接配置，属新增对接需求。
待办
明确库的类型 / 连接信息 / 权限 / 表结构 / 白名单；方案建议「读接入 + 写隔离」——商品会员等按需读或同步，交易数据仍写 H5 自有库；开发适配映射层。
依赖
小程序数据库连接信息 + 开放 H5 服务器 IP 白名单
预估
1~2 天（涉及迁移或复杂映射则 3~5 天）

3. 短信验证码登录（需申请资质）

现状
短信发送代码已完整实现（直连腾讯云短信 API，无需额外 SDK），但当前为 debug 模式：未配凭证时自动回显验证码并放行万能码，仅供内部调试。前端手机号 + 验证码流程已就绪。
待办
Capri 侧：腾讯云实名 → 申请短信签名（需营业执照 / 公众号或小程序佐证）→ 申请验证码模板 → 等审核。开发侧：填凭证 → 关闭 debug 万能码 → 真机验证。
依赖
腾讯云短信签名 + 模板审核通过
预估
审核 1~3 个工作日；配置验证 0.5 天

4. 微信支付分账（需进一步研究并落实）

现状
支付走服务商模式，接口完整：下单（微信内 JSAPI / 外部浏览器 H5）、查询、关闭、退款、回调验签、状态自检均已实现，支付成功后自动流转订单并落流水。分账：下单带自动分账标记依赖平台配置；代码中主动分账接口的接收方与分成金额为占位（写死 0），尚无真实比例计算。
待办
配置侧：确认 APIv3 密钥、商户私钥、服务商 AppID 授权到位。研究侧（核心）：明确谁分给谁、按什么比例、什么时机分。开发侧：分成金额计算 + 接收方配置 + 对账。
依赖
微信支付平台配置 + 分账业务规则（需业务 / 财务确认）
预估
配置 1 天；分账规则明确后开发 2~3 天

关键路径上的三个「等待项」= 服务器 / 短信 / 微信支付，其余工作可在等待期先做。

整体工期由 3 个等待项（服务器 / 短信 / 微信支付）决定；B 类与开发侧的工作可在等待期先做完，等待项一到位即可快速收口。等待期可并行推进：小程序数据库只读接入与字段映射、支付宝申请与开发、配置外置与工程化改造、端到端联调脚本与用例准备、智能体卡片渲染复核。
整体预期（可并行推进）
· 乐观：等待项 1 周内齐备，支付宝与微信支付并行开发 —— 约 3 周完成。
· 现实：含采购、审核、规则确认的正常等待 —— 约 4~6 周完成。
· 风险最大项：微信分账（业务规则需先定，不确定性最高）。

五、风险提示与建议

  • 等待项是最大变量：服务器部署、短信对接、微信支付对接三项时间不可控，建议尽早发起、持续跟进；其余项（数据库、支付宝及开发工作）可在等待期先行推进，避免空等。
  • 分账规则优先拍板：唯一「技术已备、规则未定」的项，规则不定则无法估算准确工期，建议尽快与业务 / 财务拉齐。
  • 数据库先做只读评估：小程序库建议先只读接入验证字段，写操作留在 H5 自有库，降低耦合与数据风险。
  • 工程化一次到位：本次迁移是补 systemd / 部署脚本 / 配置外置的好时机，避免后续每次发版都人工操作。
  • 支付宝与微信支付互不依赖：支付宝申请可自行启动，可并行推进；若上线时间紧，可先保微信支付（微信内流量为主）。
  • 安全底线：所有密钥 / 证书只进服务器环境变量，不入仓库；上线前务必关闭短信 debug 万能码。
本报告基于 2026-09-15 对代码仓库的实地盘点生成；外部账号与平台配置状态建议与实际持有情况核对后再定稿。
