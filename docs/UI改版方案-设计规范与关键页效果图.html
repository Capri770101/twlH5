跳舞兰 AI 花店 · UI 改版方案

面向 H5 与微信小程序的统一设计规范，以及 6 个关键页面的高保真效果图。 本稿用于评审确认设计方向，确认前不改动任何线上代码。

评审稿 v1 2026-09-18 视觉方向：暖调花艺 · 温柔治愈 覆盖：H5 + 小程序 状态：待评审
01

改版判断：先定规范，再改页面

当前 H5 与小程序的样式是「从 `app.wxss` 1:1 移植」来的，颜色、字号、圆角都散落在各页面里，改一处很难统一。 所以这次不直接改页面，而是先立一套两端共用的设计 token，再让页面去消费它。

1核心问题

  • 品牌色缺位：logo 的金橙是跳舞兰的天然主色，线上却完全没用，主色是偏灰的玫瑰粉
  • 字号偏小：正文 26rpx（375 宽下仅 13px），长时间阅读偏累
  • 页面各自定义间距圆角，同类卡片长得不一样
  • AI 顾问页只呈现文字气泡，平台返回的卡片结构被丢弃

2本次要解决

  • 用 logo 反推一套有依据的品牌色板，补上金橙主色
  • 建立字号 / 间距 / 圆角 / 阴影四套刻度，写成 CSS 变量
  • 统一核心组件（按钮、卡片、标签、状态流、空态）
  • 重做 AI 顾问页的信息结构：文字 + 方案卡 + 商品卡 + 效果图

3本次不做

  • 不改任何页面代码，不动构建与部署
  • 不引入新的 UI 框架或组件库
  • 不重做信息架构与路由（沿用现有 22 个页面）
  • 不改业务逻辑与接口
02

03

文字阶梯

沿用 750rpx 设计稿基准（下图右侧为 375pt 宽下的实际观感）。核心调整：正文从 26rpx 提到 28rpx，并把原先散落的 7 级收敛为 8 级、每级都有明确用途。

不要用 26rpx 以下做正文。当前项目里 --fs-body 就是 26rpx，等于 375pt 屏上的 13px，低于移动端正文 14px 的通用基线；再叠加暖色调低对比度，可读性会明显变差。

04

间距 · 圆角 · 阴影

间距走 8 的倍数（rpx 侧即 16 的倍数）；圆角收敛为 6 档；阴影改用暖褐色投影替代纯黑，这是"温柔治愈"最关键的一个细节 —— 纯黑阴影会让暖色页面发脏。

S间距刻度

xs · 8rpx · 图标与文字
sm · 16rpx · 同组元素
md · 24rpx · 卡片内边距
lg · 32rpx · 页面左右边距
xl · 48rpx · 区块之间

R圆角刻度

  • 8px 小圆角 —— 标签、徽标
  • 12px 中 —— 缩略图、输入框
  • 16px 大 —— 商品卡、列表块
  • 22px 特大 —— 主卡片、底部弹层
  • 28px 超特 —— Hero 区、页头
  • 999px 胶囊 —— 按钮、筛选 chip

E阴影与层次

  • sm 0 2px 8px / rgba(120,95,60,.04) —— 列表卡
  • md 0 6px 20px / rgba(120,95,60,.07) —— 悬浮卡
  • lg 0 14px 40px / rgba(120,95,60,.10) —— 弹层
  • gold 0 8px 22px / rgba(245,160,19,.28) —— 主按钮

主操作恒为金橙渐变 + 金色投影；次操作为金线描边 + 浅金底；破坏性操作（退款/取消订单）用珊瑚红实心；禁用态用中性灰底，不降透明度（暖色底下降透明度会显脏）。

状态标签 & 订单状态流

待支付 待接单 商家已接单 配送中 已完成 退款中 已取消

标签一律用「浅底 + 同色系深字 + 细描边」，不用实心色块 —— 实心会和金色主按钮抢视觉焦点。「商家已接单」这类来自商家后端的状态需要额外标注来源（见第 06 节订单页），让用户明白进度不是平台自说自话。

07

AI 顾问页：改什么、为什么

这是你提到体验最弱的页面。问题不在视觉，而在信息结构 —— 平台其实返回了卡片、方案、效果图任务等结构化数据，但前端只取了纯文本。

维度现状改版后
消息内容 只有文字气泡，平台返回的卡片结构被丢弃 文字 + DIY 方案卡 + 商品卡 + 效果图混合呈现
等待反馈 长时间空白，用户不知道 AI 在做什么 显示「正在生成花束效果图…」等具体阶段，并带进度动效
方案呈现 文字描述花材，无法直接下单 方案卡结构化展示花材/花语/价格，并给出可直接下单的商品
后续引导 需用户自己想下一句问什么 提供快捷追问 chip（更便宜的 / 换颜色 / 写贺卡）
会话管理 刷新后历史不可靠，卡片易丢失 方案与卡片本地持久化 + 顶部历史入口，刷新不丢
合规标识 未展示 AI 生成标识 常驻「本内容由 AI 生成，仅供参考」
i

这页的改动主要在信息结构，视觉只是承载。设计确认后，实施时还需要同步处理流式返回（逐字推送与回撤）、卡片本地持久化等已在技术侧记录的问题，否则会出现「只有卡片没有文字」或「刷新后方案消失」。

08

H5 与小程序如何共用一套规范

同一套 token，两种落地方式。这样后续任一端的视觉调整，都能低成本同步到另一端。

项目H5（Vue3 + Sass）小程序（wxss）
颜色 / 阴影tokens.scss 里的 CSS 变量app.wxss 同名 CSS 变量
字号 / 间距沿用 --rpx：n rpx = n/750 rem直接用 rpx
圆角变量换算成 rem变量换算成 rpx
图标统一改用 SVG（当前是 png 位图，改色需重新导图）SVG 或 iconfont
布局骨架固定高容器 height:100dvh + 内部滚动页面自然滚动 + 固定底部栏
禁用事项不要用 vw（容器上限 480px，桌面必溢出）不适用
09

需要你和同事一起拍板的 6 件事

这几项会显著影响后续实施量，建议在评审会上逐条给出结论。

1主色是否换成金橙

  • 换成金橙：更贴 logo 与「文心兰」花材本色，识别度更高
  • 保留玫瑰粉：改动小，但与 logo 关联弱
  • 我的建议：换成金橙，玫瑰粉降为礼赠场景情绪色。

2是否保留薄荷绿

  • 薄荷绿 #4ECDC4 在整套色板里最不呼应 logo
  • 建议仅保留在物流轨迹等少数位置

3图标是否重做

  • 现在底部导航是 5 组 png 位图（含 active 态共 10 张）
  • 换主色后位图无法改色，必须重新导图
  • 建议一次性换成 SVG，后续改色零成本

4首页 Hero 的取舍

  • 现方案把 Hero 完全让给 AI 入口
  • 若更看重商品转化，可改为「AI 入口 + 首屏商品」并存

5订单进度是否展示商家来源

  • 接入商家后端后，进度由门店驱动
  • 建议明确标注「来自门店」，把真实性做成卖点

6实施顺序

  • 建议：设计 token 落地 → 组件统一 → 逐页替换 → AI 页重构
  • 是否先只改 H5、小程序后续跟进，请在评审时确认
!

本稿仅为设计方向确认，尚未改动任何线上代码。评审结论确定后，再按「token → 组件 → 页面」的顺序实施，每一阶段都可独立上线与回滚。
