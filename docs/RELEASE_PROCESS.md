# Release Process

## 版本与范围

1. 每次变更先确定目标版本和用户可见影响。
2. 更新 `CHANGELOG.md`，不得在发布后补写。
3. 一个发布只包含已经审阅的改动；工作区中其他未完成改动不得混入构建产物。

## 发布前

1. 检查 `git status`、差异和最近提交，识别未关联当前版本的改动。
2. 运行对应测试与 `npm run build`。
3. 记录构建产物、版本、验证命令和预期验收场景。
4. 在生产服务器备份当前静态 `dist`，并确认 `twlh5-api` 与 `flower-shop` 状态。

## 发布

1. 上传构建产物到新目录，检查 `index.html` 存在。
2. 原子切换静态目录。
3. 只重启 `twlh5-static`；不得为静态发布重启业务 API、商家服务或数据库。

## 发布后

1. 检查 `twlh5-static`、`twlh5-api`、`flower-shop` 均为 active。
2. 验证静态服务本机端口、域名本机 HTTPS 和公网 HTTPS。
3. 执行本版本的关键用户场景，并把结果补入版本记录或发布工单。
4. 发现异常优先使用备份 `dist` 回退；回退本身也必须记录版本与原因。
