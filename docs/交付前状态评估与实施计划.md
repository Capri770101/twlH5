## 一、总体结论

**一句话：产品与代码已基本就绪，交付的真正瓶颈是「外部资源到位」，而不是开发工作量。**

- 前端 H5 全部页面、核心交互与体验优化**已完成并上线验证**；后端订单 / 用户 / 支付 / 短信的代码骨架**完整**，多数只差「填凭证 + 配平台 + 联调」。
- 6 项遗留里：**3 项需等待外部**（服务器部署、短信对接、微信支付对接），**2 项可主动推进**（小程序数据库、支付宝申请），另有 1 项（真实订单端到端）待前面就绪后联调。
- 除 3 个等待项外，其余工作可在等待期先行推进；**等待项一到位，具备在 3~4 周内完成全部交付**的条件。

## 三、六项问题逐条说明

### 1. 服务器（旧机已弃置，等待新服务器）

**现状**
- 系统为三段式架构：① 静态站点 + 智能体反代（Node，:8088）→ ② Nginx（:443，`/` 转 8088、`/api/` 转 4000）→ ③ 业务后端（Express，:4000）。
- 当前部署**强绑定固定 IP**：业务配置里写死了旧服务器地址（`8.138.248.173`），另有历史只读库地址（`118.25.21.45`）与商品数据 API 域名。
- 仓库内**没有入库 systemd / pm2 / Docker 等进程管理配置**，静态服务目前靠人工后台常驻，属于「能跑但不够工程化」。

**待办**
- 开发侧：把硬编码的 IP / 域名 / 端口全部抽成环境变量；补齐 Nginx 配置、进程守护（systemd）、一键部署脚本。
- 交付侧：新服务器开通 → 安装运行环境（Node + Nginx + MySQL）→ 部署迁移 → 重新签发/迁移 HTTPS 证书 → 域名解析切换。

**依赖**：新服务器（IP、登录方式、规格）。

**预估**：服务器到位后，环境搭建 + 迁移 + 验证约 **1~2 天**。

---

### 2. 数据库接入（连接小程序数据库）

**现状**
- 目前有两套库：① 业务库 `h5_shop`（本机 MySQL，承载用户 / 地址 / 订单 / 支付 / 短信表，建表脚本已入库）；② 历史只读库 `flower_shop`（已不再用于读路径，商品数据改走合作方 API）。
- **代码库中目前没有任何「小程序数据库」的连接配置**，属于新增对接需求。

**待办**
- 需先明确（见第四节）：小程序数据库的类型、连接信息、账号权限、表结构、IP 白名单。
- 方案决策：建议采用**「读接入 + 写隔离」**——商品 / 会员等数据按需读小程序库或同步，订单、支付等交易数据仍写 H5 自己的业务库，避免两套系统强耦合、互相影响。
- 开发侧：编写适配 / 映射层，做字段对齐；必要时做一次性数据迁移与同步策略。

**依赖**：小程序数据库连接信息（类型、地址、库名、账号、表结构、白名单）。

**预估**：拿到信息后 **1~2 天**（若涉及数据迁移或复杂映射，**3~5 天**）。

### 3. 短信验证码登录（需申请资质）

**现状**
- 短信发送代码**已完整实现**（直连腾讯云短信 API，无需额外 SDK），但当前处于 **debug 模式**：未配置凭证时自动回显验证码，并放行一个万能验证码，仅用于内部调试。
- 前端登录页「手机号 + 验证码」流程已就绪。

**待办**
- **Capri 侧（资质）**：腾讯云账号实名 → 申请**短信签名**（需营业执照 / 公众号或小程序佐证）→ 申请**验证码类短信模板** → 等待审核通过。
- 开发侧：填入凭证 → **关闭 debug / 万能码** → 真机验证收发。

**依赖**：腾讯云短信签名 + 模板审核通过（含相关资质材料）。

**预估**：资质审核 **1~3 个工作日**；配置与验证 **0.5 天**。

### 4. 微信支付分账（需进一步研究并落实）

**现状**
- 支付走**服务商模式**，代码完整：下单（微信内 JSAPI / 外部浏览器 H5）、查询、关闭、退款、回调验签与状态自检均已实现，支付成功后自动把订单从「待支付」转「待接单」并落支付流水。
- **分账**：下单时带「自动分账」标记，依赖微信平台侧配置生效；代码里另有「主动分账」接口，但**分账接收方与分成金额目前是占位（金额写死为 0），没有真正的比例计算**。
- 子商户号已按店铺维护（多店映射表已入库，含商户号信息，不进公开仓库）。

**待办**
- 配置侧：确认 APIv3 密钥、商户私钥、服务商 AppID 授权三项平台配置到位。
- 研究侧（**核心**）：明确分账业务规则——**谁分给谁、按什么比例、在什么时机分**（支付后立即分 / 分账冻结 / 售后解冻等）。
- 开发侧：实现分成金额计算 + 分账接收方配置 + 分账结果对账。

**依赖**：微信支付平台配置（密钥 / 授权）+ 分账业务规则（需业务/财务确认）。

**预估**：平台配置 **1 天**；分账规则明确后开发 **2~3 天**。

## 五、实施计划与时间预期

**关键路径**：新服务器到位 → 部署与数据库落地 → 支付 / 短信配置 → 真实订单闭环 → 验收。
关键路径上的三个「等待项」= **服务器 / 短信 / 微信支付**，其余工作可在等待期先做。

| 阶段 | 任务 | 前置 | 工期（开发） | 等待 |
|---|---|---|:---:|---|
| 阶段 0 | 等待期并行项（数据库只读接入、支付宝申请、配置外置与工程化、联调用例准备） | — | 可立即开始 | — |
| 阶段 1 | 新服务器环境搭建 + 代码部署 + 业务库重建 + 域名/证书迁移 | 新服务器 | 1~2 天 | 🚧 服务器到位 |
| 阶段 2 | 小程序数据库对接 | 库信息 | 1~2 天（复杂则 3~5 天） | 对方配合 |
| 阶段 3 | 短信真发上线 + 手机号登录闭环 | 短信资质 | 0.5 天 | 🚧 审核 1~3 工作日 |
| 阶段 4 | 微信支付配置 + 真实订单闭环 | 平台配置 | 1~2 天 | 🚧 配置 1~2 天 |

**推进策略：等待期不空转**

整体工期由 **3 个等待项**（服务器 / 短信 / 微信支付）决定；B 类与开发侧的工作可在等待期先做完，等待项一到位即可快速收口。等待期可并行推进：小程序数据库只读接入与字段映射、支付宝申请与开发、配置外置与工程化改造、端到端联调脚本与用例准备、智能体卡片渲染复核。

**整体预期（可并行推进）**

- **乐观**（等待项 1 周内齐备，支付宝与微信支付并行开发）：约 **3 周**完成。
- **现实**（含采购、审核、规则确认的正常等待）：约 **4~6 周**完成。
- **风险最大项**：微信分账（业务规则需先定，属研究型工作，不确定性最高）。

## 六、风险提示与建议

1. **等待项是最大变量**：服务器部署、短信对接、微信支付对接三项时间不可控，建议**尽早发起、持续跟进**；其余项（数据库、支付宝及开发工作）可在等待期先行推进，避免空等。
2. **分账规则建议优先拍板**：这是唯一「技术已备、规则未定」的项，规则不定则无法估算准确工期，建议尽快与业务/财务拉齐。
3. **数据库对接先做只读评估**：小程序库建议先只读接入验证字段，写操作留在 H5 自有库，降低耦合与数据风险。
4. **工程化补齐**：本次迁移是补 systemd / 部署脚本 / 配置外置的好时机，一次到位可避免后续每次发版都人工操作。
5. **支付宝与微信支付互不依赖**：支付宝申请你可自行启动，可与微信支付并行推进；若上线时间紧，可先保微信支付（微信内流量为主）。
6. **安全底线**：所有密钥 / 证书只进服务器环境变量，不入仓库；上线前务必关闭短信 debug 万能码。
